# HealGen arXiv Paper (Phase C) + Submission Kit (Phase D) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Write, compile, and verify an arXiv-ready LaTeX paper for HealGen whose every number and figure traces to committed prototype results, plus the Phase D submission kit (arXiv mechanics, endorsement plan, cover comment).

**Architecture:** One LaTeX root `paper/main.tex` (IEEEtran conference class) with `paper/refs.bib`, figures in `paper/figures/`, and tables in `paper/tables/` — all tables generated by `prototype/experiments/make_tables.py` from `results/*.csv` (never hand-written). Prose is written from the research docs (`research/01..03`) and the actual implementation, section by section, compiling after each task. Compiled with the local Tectonic binary (`.tools/tectonic.exe`).

**Tech Stack:** LaTeX (IEEEtran), Tectonic 0.17.0 (local, `.tools/tectonic.exe`), matplotlib-generated result figures (existing `make_tables.py`), TikZ for the architecture diagram, Python for figure/table generation.

**Spec:** `docs/superpowers/specs/2026-10-26-verigen-arxiv-design.md` (binding authority) + `research/01-prior-art.md`, `research/02-differentiation.md`, `research/03-eval-methodology.md` (content sources) + `docs/superpowers/plans/2026-10-26-healgen-prototype.md` (result artifacts this plan consumes).

**Precondition:** prototype plan Tasks 14–16 complete — `results/system_summary.csv`, `results/pairwise_tests.csv`, `results/ablations.csv`, `results/claims.csv`, `results/judge_validation.json`, `paper/tables/*.tex`, `paper/figures/*.png` all exist. This plan must not start before them.

## Global Constraints

- **Honesty (design §4, §8.1):** no numeric value is typed into `.tex` by hand. Every number in prose/abstract comes from a `\newcommand` macro emitted by `make_tables.py` from a CSV column, or from an `\input{tables/...}` file. Architecture/section text may describe behavior but not assert measured values.
- **No overclaiming (design §8.1):** framed as architecture + measurement paper; headline claims are about claim-level self-healing design and measured trade-offs, never "beats SOTA". Results reported whatever they show.
- **Honest scoping (design §4):** abstract/limitations state plainly: small-scale CPU prototype, flan-t5-base generator, HaluEval N=150, BM25 retrieval, NLI judge — not a production system, not large-LLM evaluation.
- **Wording must follow the code (ledger rulings):** draft-first claim decomposition (R2 — NOT "pre-generation decomposition"), hybrid support rule = normalized-substring OR NLI entailment (R8 — must be documented in Method + Limitations with pure-NLI sensitivity noted).
- **Title/name (design §8.5):** system is **HealGen**; title working form: *"HealGen: Claim-Level Evidence-Sufficiency-Guided Self-Healing Inference for Factual LLM Generation"*. "VeriGen" appears nowhere in the paper.
- **Citations:** only BibTeX entries whose arXiv IDs/venues are verified in `research/01-prior-art.md` (it carries exact BibTeX keys); uncited novelty claims are forbidden — every related-work assertion gets a `\cite`.
- **Compiler:** `.tools/tectonic.exe` (Windows). Compile command: `& .\.tools\tectonic.exe paper\main.tex` run from repo root. arXiv compatibility: standard IEEEtran + tikz only, no exotic packages (arXiv builds with its own TeXLive).
- **Figures:** architecture diagram is TikZ inline (vector, no extra toolchain); result figures + DCEG come from the prototype (`make_tables.py` outputs, `prototype/figures/dceg_example.png`).
- Repo root: `C:\Users\princ\Downloads\builder\verigen`.

## Review Focus

1. **A number in prose that does not trace to a CSV** (abstract/intro/conclusion are the temptation) — pinned by Task 7's trace-back spot check: pick two prose numbers, grep the source CSV.
2. **Overclaiming or SOTA language sneaking into abstract/limitations** — pinned by Task 7's `grep -i` sweep for banned phrases (`state-of-the-art|outperform|superior|SOTA`) with allowed results-only contexts reviewed by hand.
3. **Method section describing a system the code does not implement** (pre-generation decomposition, per-claim risk without CRE degeneracy note, repair actions list vs `repair.py`) — pinned by Task 4's cross-check step against `prototype/healgen/*.py`.
4. **Citation/claim mismatch** (a `\cite` for a claim the cited paper doesn't support, or a related-work claim with no `\cite`) — pinned by Task 3's step: every related-work paragraph sentence carrying a novelty/comparison claim must contain at least one `\cite`.
5. **`\input`/`\includegraphics` file missing at build** (tables regenerated under a different name, DCEG path wrong) — pinned by every task's compile step (tectonic hard-fails on missing `\input`); plus Task 5 step asserting all `paper/tables/*.tex` named in `main.tex` exist on disk.
